# MemoryBloc 业务逻辑

memory 域的工作流编排。通用引擎（scan / judge / merge）在 `core/engine.dart`，这里装 memory 特有的编排逻辑——那些不属于通用引擎、只属于记忆结构的判断。

## 四步流程（journal-to-* 的编排）

每条工作流（classify / grade / cluster / promote）都走同一条流水线：

1. **扫描**（scan）：按关键词表定位候选——认知类（发现、原来、其实、关键是…）、意图类（要、不要、别、澄清…）、方向类（决定、优先、待定…）
2. **过滤**（judge）：三问判断去向，拿不准不收
3. **聚类**（judge + merge）：同一认识跨日期合并为一条，判断依据是本质相同而非措辞相似
4. **合并**（merge）：新线索增条目，已有条目就地改写，被推翻的替换，重复的留互链

MemoryBloc 的职责是把这四步按序组装，每步的结果喂给下一步。

## 三问分层路由

一条日志可能同时命中多层。分层规则：

| 问题 | 去向 |
|---|---|
| 「想通了什么」（X 其实是因为 Y） | insight |
| 「我是什么样的人」（反复怎么判断） | profile |
| 「我要做什么 / 选什么」 | roadmap |
| 「我到底想要什么」（要 X 不要 Y） | intention |
| 「发生了什么」 | 留 journal |

**去重逻辑**：同一内容在多层出现时只写各自侧面，不整段复制。insight 写成可对错的命题，roadmap 写成决策或状态，intention 写成给 AI 的指令式意图。已是决策且指令不新增信息的，intention 不重复收录（以 roadmap 为准）。

## 证据分级

- 多日重复或有验证 / 应用行动 = **已确认**
- 单次想通、未验证 = **假说**
- 被后续日志推翻 = 就地改写或移除，以最新为准

**升降级**：命题反复套用、稳定为思维框架后，晋升到 profile 的方法论文件（insight 改写为互链）；命题引出选择后，选择分流到 roadmap，insight 只留命题。

## 合并策略

四种情况四种处理：

| 情况 | 处理 |
|---|---|
| 新线索 | 增条目 |
| 已有条目 | 就地改写（不是追加） |
| 被推翻 | 直接替换 |
| 重复 | 留互链，不重复收录 |

## 边界

- 不收感受与情绪（归 profile 的情绪文件）
- 不收事件经过（留 journal）
- 不给建议、不写「所以要做什么」（归 roadmap）
- 单位是认识线索，不是日期文件——多对多
