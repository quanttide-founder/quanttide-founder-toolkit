# FictionBloc 业务逻辑

fiction 域的工作流编排。通用引擎（scan / judge / merge）在 `core/engine.dart`，这里装 fiction 特有的编排逻辑——那些不属于通用引擎、只属于创作结构的判断。

## 素材流向（观察站 → 小说）

创作素材的流转路径：

```
观察站/1_情绪日记  →  发现母题  →  {小说}/1_灵感
观察站/2_社会观察  →  发现场景  →  {小说}/2_场景
```

FictionBloc 的职责是把「从情绪素材到创作片段」这条流水线编排好。当前实验表明：直接从情绪跳到场景素材会产出「金句」而不是「画面」——中间需要一步**观察展开**（先写具体的外部观察：场景、动作、细节，再从观察里长出片段）。

## 三步提炼（journal-to-fiction 的编排）

1. **取样**（scan）：从观察站按主题关键词定位可写素材
2. **观察展开**（judge）：从情绪记录里提取外部观察——具体场景、动作、细节，不是抽象感受
3. **落实片段**（merge）：把观察写成场景素材（50 字钩子）+ 母题卡片（一句话说清写什么）

**判据**：拿到素材知道怎么下笔 = 通过；「不知道怎么写」= 观察展开不够，退回第二步。

## 章节编号轴的维护

fiction 域特有的约束：

| 规则 | 说明 |
|---|---|
| 单层连续编号 | `{序号}_{标题}.md`，每个场景文件即一章 |
| 跨阶段共用编号轴 | 初稿/改稿/定稿的同序号文件是同一章的不同版本 |
| 预留空号 | 为计划补写的章节留号，宁空勿移 |
| 不重排 | 新章写入空位或当前最大号 +1 |
| `0_` 前缀 | 前言等非正文文件，不占正文章节号 |
| 未编号 | 替代草稿不编号，保留原名放在初稿目录 |

FictionBloc 负责维护这条编号轴——发现空号、检查冲突、分配新号。

## 阶段流转

各小说阶段名不同，但流转方向一致：

```
1_灵感（素材） → 2_场景/提纲 → 3_初稿 → 4_改稿 → 5_定稿/成稿
```

- 素材在阶段间流转时**同一序号多份**——靠阶段区分版本
- 阶段目录按 `{N}_{名称}` 动态发现，不硬编码阶段名
- 一个阶段的完成判据：该阶段的章节都已编号且无空位

## 包装文案（晋江规范）

标题、一句话简介、立意三类文案各自承担不同信息，不互相重复：

| 文案 | 职责 | 约束 |
|---|---|---|
| 标题 | 核心矛盾与钩子 | 直白、具体、有画面感或反转的长句优先 |
| 一句话简介 | 标题之外的增量信息 | 不超过 15 字，回答「凭什么看」 |
| 立意 | 价值维度 | 正向，与文案结尾呼应 |

FictionBloc 在作品进入定稿阶段时生成包装文案——从正文提取具体细节（台词、场景、意象）做钩子。

## 边界

- 观察站是人类素材，实验室是 AI 产物——两个不同的集合，不混在一起
- 创作日志/创作谈/创作设定归 memory 仓库的 `write/` 记忆集，不在 fiction 里
- 各小说 `1_灵感` 只保留该小说专属的母题素材，不存通用创作日志
